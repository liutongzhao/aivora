# Aivora 上线收口设计

**日期：** 2026-10-10

## 目标

在不扩展支付、统计和复杂设备绑定的前提下，完成 Aivora 上线售卖所需的核心权限闭环：用户登录后只能在拥有有效期限授权或剩余免费体验次数时开始 AI 任务；额度、授权和账号状态变化能够及时反映到桌面端；异常情况下不误扣额度、不继续使用失效会话。

## 范围

### 1. 桌面端权限门禁

复用现有 `apps/desktop/src/services/usageEntitlement.ts` 的额度判断能力，在所有任务开始入口统一调用权限检查。覆盖：

- 通用搜题
- 单选题
- 多选题
- 编程题
- 代码调试

门禁必须在截图采集或任务提交之前执行。后端权限判断始终是最终准则，桌面端门禁仅用于提前反馈。

### 2. 明确的用户提示

桌面端根据后端返回的额度状态显示可理解的中文提示：

- 未登录：请先登录
- 免费体验次数已用完：请激活授权码
- 授权已过期：请激活新的授权码
- 账号已停用：账号已被停用，请联系管理员
- 服务不可用：暂时无法确认使用权限，请检查网络后重试

提示应阻止任务开始，不应只写入控制台。

### 3. 状态同步

- 登录成功后刷新当前额度。
- 任务结束、失败、取消后刷新当前额度。
- 授权码在 Web 端激活后，桌面端下一次检查必须获得最新状态。
- 退出登录或会话失效时清理本地用户和额度缓存。
- 账号被停用或会话失效时，桌面端停止继续提交任务并引导重新登录。

### 4. 重复提交和异常处理

- 已在处理中的任务不能重复提交。
- 网络失败时不能把“无法确认权限”当作“允许使用”。
- 后端任务使用已有预约、失败回滚机制。
- 桌面端不得自行减少或永久缓存额度，以服务器返回为准。

## 不在本轮范围

- 支付系统
- 授权码导出
- 数据统计图表
- 复杂设备绑定和设备数限制
- 多级管理员权限
- 用户反馈中心
- 自动升级体验优化

## 验收标准

1. 没有免费次数、没有有效授权的账号，所有任务开始入口均不可提交。
2. 有免费次数的账号可以开始任务，并在任务完成后看到最新剩余次数。
3. 有有效授权的账号不受免费次数限制，桌面端显示授权到期时间。
4. 授权过期、账号停用、会话失效时有明确提示，不能继续提交任务。
5. 网络异常时任务不会被误放行。
6. 重复点击不会产生重复任务。
7. 桌面端单元测试、Web 测试、后端测试、TypeScript 检查和生产构建全部通过。
