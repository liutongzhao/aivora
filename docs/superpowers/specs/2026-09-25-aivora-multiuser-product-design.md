# Aivora 多用户产品化重构规范

**日期：** 2026-09-25
**状态：** 待产品与技术评审
**性质：** 产品需求与架构设计；不是可直接执行的开发任务清单

## 1. 目标与决策

Aivora 应从本地搜题演示系统升级为可供多名用户同时使用的产品。桌面端负责采集和即时查看；网页端负责配置、检索、复习和管理。保留现有截图、快捷键、题型处理、远程控制等能力，但重新设计页面结构与交互。

本规范记录本次已确认的产品决策；如产品策略改变，先修订规范再调整实现：

1. **BYOK-only：** 每个用户只能使用自己保存的 API 地址、密钥及模型配置调用模型。平台和管理员不提供共享模型密钥、共享额度或隐式回退。
2. **用户数据隔离：** 普通用户只能读取和修改自己的任务、答案、截图、设备、密钥、提示词与设置；管理员仅通过明确授权的管理接口访问用户业务数据。
3. **并发处理：** 不允许一个用户的推理任务占住整个服务；系统应排队并同时执行多个用户的任务，且每个用户有独立的状态和事件。
4. **答案优先：** 桌面悬浮窗不要求点击；选择题实时显示答案与分析，编程题实时显示代码。原始 JSON 不出现在主视图。
5. **先设计再开发：** 桌面端和网页端必须先交付可审查的页面布局、状态图与交互稿，确定后再逐页实现；不能只在现有页面上换颜色和增加卡片。

旧规格 `2026-09-24-aivora-platform-design.md` 与 `2026-09-24-aivora正式产品化设计.md` 描述的是基础闭环；**本规范在多用户、BYOK-only、增量字段流和页面重构方面优先于旧规格**。旧实施计划不直接用于执行本次重构，应按本规范重新分期。

### 1.1 验收范围

本轮包括服务端并发、租户隔离、每用户模型接入和提示词、流式字段渲染、编程语言、桌面端重构、Web 用户端及管理员端重构、监控与测试。不包括支付、充值、团队共享空间、管理员代用户调用模型、第三方模型采购。

## 2. 现状与已确认的差距

| 现有基础 | 产品化差距 |
| --- | --- |
| FastAPI、Celery、Redis Streams、PostgreSQL、MinIO、Electron、Next.js 已形成截图到答案闭环 | 本地 Worker 使用 `solo` 单任务执行，尚未通过多人并发与失败注入验证 |
| 任务与文件记录 `user_id`，普通任务接口按用户过滤 | SSE 使用独立短时 token；管理员截图访问、跨用户设备/配置和事件边界需要统一审计与越权测试 |
| 有模型目录、用户默认模型配置和 `prompt_templates` 表 | Worker 仍取全局 `ai_model` 和 `ai_api_key`；提示词从代码注册表读取，用户选择没有贯彻到推理 |
| 后端逐段发送原始 JSON，完成后存储 `parsed` | 桌面选择题等待完整结果，编程题生成中先展示原始流，再切换代码；断线重连缺少字段级去重契约 |
| 后端任务请求有 `language` 字段 | 桌面 SSE 提交未传语言；网页也缺少完整的语言选择与任务快照展示 |
| Web 有任务、历史和管理员页面 | 工作台冗余留白，历史点击不可用，答案以 JSON 字串为主，管理员不能查看完整截图与解答，缺少明显的退出入口 |

这些是代码盘点结果，不代表现有部署已经完成性能或安全审计。

## 3. 总体方案与边界

采用**分阶段演进现有模块化单体**，不另建一套账号或任务系统：

```text
Electron / Web
  -> 身份认证、任务创建、配置与文件 API
  -> Redis / Celery 按用户公平排队
  -> Worker 按任务快照加载该用户的密钥、模型、提示词和语言
  -> 模型原始流 -> 结构化字段事件 -> Redis Streams
  -> 桌面悬浮窗 / Web 任务详情订阅字段事件
  -> 最终答案和配置版本落 PostgreSQL，截图落私有对象存储
```

**职责边界：**

- API：鉴权、所有权检查、配置校验、任务创建、截图授权、管理操作；不在 HTTP 请求内等待模型推理。
- Worker：领取任务、校验取消状态、加载任务配置、访问用户模型、输出字段事件、保存结果与失败状态。
- 数据库：用户归属、任务状态、答案、模型/提示词版本、管理员审计；不得保存明文密钥。
- Redis：排队与短期事件回放；不是唯一的结果存储。
- Electron：截图与免点击的即时答案；不保存用户模型 API 密钥。
- Web：个人设置、历史复习和管理员监管；不把服务端密钥下发给浏览器。

## 4. 用户与权限

### 4.1 普通用户

- 注册、登录、退出、查看当前设备与会话；退出后清除本地会话并撤销服务端会话。
- 配置自己的服务商 API 地址与密钥；管理自己的模型、按题型的默认选项、提示词版本和编程语言。
- 提交、取消、检索、查看、删除自己的任务与历史；查看自己的截图、结构化答案和解析警告。
- 通过自己的已授权设备使用远程控制。
- 没有可用的个人密钥、模型不支持图像、或连接测试不通过时，提交入口给出清楚的原因；**不得自动使用平台密钥**。

### 4.2 管理员

- 可查看用户状态、注册时间、最近活动、任务量与错误概况；启停用户、撤销会话，操作必须留审计记录。
- 可按用户/题型/状态/时间检索任务，并在有明确管理权限的接口中查看截图、答案、错误和配置版本。
- 不能读取用户明文 API 密钥；只能看到服务商、模型、掩码与配置状态。不能替用户修改提示词、模型选择或偷偷调用其密钥。
- 管理截图访问记录应包含操作者、目标用户、任务、时间和访问理由；界面提示数据敏感。管理员自己的搜题也必须配置自己的密钥。
- 后端 `require_admin` 是权限边界；页面上的隐藏按钮只改善体验，不构成授权。

### 4.3 隔离约束

所有用户资源查询必须带服务端确定的 `user_id`；不接受客户端传来的 `user_id` 作为授权依据。任务、答案、截图、设备、模型配置与提示词按归属检查。SSE token 绑定任务和用户，短时有效、可撤销；重连或刷新 token 不得延长原任务权限。跨用户请求统一返回不可枚举的 404/拒绝结果。对象存储保持私有；签名截图 URL 仅在授权后生成，短时有效，不公开桶。

## 5. 多用户任务与可靠性

### 5.1 生命周期

`queued -> loading_images -> streaming -> completed`；每一步允许进入 `failed` 或 `cancelled`。状态变更必须持久化并可查询。用户提交时使用用户作用域的幂等键；重复提交不产生两个付费模型请求，客户端可重新获取合法的流访问凭据。

创建任务时解析并**固定配置快照**：所选模型及其服务商、提示词版本、目标语言与输出契约版本。后台修改配置不影响已经提交的任务。密钥不进入任务事件、日志或普通快照；Worker 从任务归属的密钥记录安全读取，密钥禁用后待执行任务进入可解释的失败状态。

### 5.2 并发与公平

- 生产环境启动多个 Worker 执行槽，数量可配置；本地 `solo` 仅用于单机调试。模型调用与对象存储读取均有限时，不占用 API 请求线程。
- 任务入队按用户做公平调度：初期每用户最多 2 个同时推理任务，其余排队；系统同时运行槽位初始为 4，部署时可调。避免单一用户耗尽全局槽位。这里是**服务保护**而非计费配额。
- 目标验收场景：至少 10 名不同用户几乎同时提交，全部创建成功；至少 4 个互不相同用户的推理可同时处于运行态，最终结果与事件不串号。供应商限流时按用户和服务商分别退避，不能使无关任务一起停止。
- 超时、可重试错误与永久错误分类；重试有上限和退避，不能让同一任务并发执行两次。Worker 崩溃后可恢复或明确失败；取消后的迟到结果不能覆盖 `cancelled`。
- 图片读取在推理前完成并有上限；长时间占用的数据库会话要拆开，不能跨整个模型流持续持有事务或连接。敏感日志禁止输出截图、原文和密钥。

### 5.3 观测与错误

记录任务 ID、匿名化用户标识、阶段、排队时长、首个有效字段耗时、总耗时、重试次数、错误码和配置版本。提供服务/队列/Worker 健康状态、运行槽位、积压量和失败率。界面区分“排队中、读取图片、连接模型、生成中、解析失败、供应商限流、已取消”；进度百分比只能表示可信阶段，不用字符数伪造预计完成时间。

## 6. BYOK 模型与提示词配置

### 6.1 用户服务商连接

每用户可创建多个 OpenAI 兼容连接：名称、HTTPS API 地址、密钥、启用状态及连接测试。保存后密钥仅显示掩码；留空表示不更改，替换需明确确认，删除连接前提示受影响的模型与任务。服务端用受管理的加密主密钥加密存储、支持轮换，主密钥不入库；日志、响应、SSE、导出和审计均不含明文。

自定义 URL 是服务端对外请求入口，必须校验方案、DNS 解析结果和重定向，拒绝内网、回环、元数据地址及非预期端口；开发环境若需本地模型，应使用**仅限本地部署的显式管理策略**，不放宽公网产品的默认保护。连接测试和模型请求均执行同一策略，并有超时、响应体大小与并发限制。

### 6.2 模型与题型映射

- 模型属于某个用户的某个连接，可设置名称、模型 ID、视觉能力、启用状态。服务端以 ID 解析，不信任客户端传入的任意模型名。
- 分别配置编程、单选、多选、通用、调试的默认模型；没有可用映射时明确阻止提交，并引导配置。
- 可在任务提交时临时选择自己已有的可用模型；选择不应修改默认值。模型名称和连接归属必须一并校验。
- 编程语言独立于模型，用户默认可选 Python 3、Java、C++、JavaScript 等，允许每次任务覆盖；语言随请求、任务快照与提示词传递，网页历史显示实际语言。未选时默认 Python 3。

### 6.3 提示词

- 按用户、题型维护系统提示词与用户模板；每次保存创建不可变版本，支持预览、恢复旧版和恢复产品默认模板。
- 默认模板是**公开的起始内容，不含平台密钥**；管理员不能静默覆盖用户模板。模板变量只允许白名单，例如图片数量、题型、语言；校验必需输出字段，不允许模板绕开输出契约。
- 任务引用确定的模板版本。用户编辑后只影响新任务。任务详情展示所用版本；管理员可审阅其内容但需权限与审计。
- 测试连接只验证供应商可用；“测试提示词”应是用户明确发起的真实模型任务，展示会消耗其自有密钥调用的提示。

## 7. 结构化流式答案协议

### 7.1 目标

模型可以持续输出 JSON，但**桌面与网页主视图永远不直接展示正在生成的 JSON**。Worker 使用能处理跨 chunk 字符串、转义、Unicode 和断流的增量 JSON 解析方式，把已确认所属字段的内容转成题型相关事件；不得用正则从半截 JSON 猜答案。解析失败时保留原文与明确警告，不宣称已有确定结果。

事件 envelope：`task_id`、单调事件序号/Redis ID、`type`、`field`、`delta` 或 `value`、`stage`、`schema_version`。建议事件包括 `answer_delta`/`answer_set`、`explanation_delta`、`code_delta`、`analysis_delta`、`warning_set`、`completed`、`failed`、`cancelled`。多选答案以稳定的选项集合事件更新，避免反复闪动单字母。字段渲染仅由事件中的 `task_id` 和题型驱动。

例如 `code_delta` 仅携带已解码的代码字符，不携带 JSON 引号或转义片段；`answer_set` 仅在完整选项标识确认后发送。字段事件的顺序可随模型输出变化，客户端不能假定答案总是第一个字段。已显示的部分内容在后续校验失败时必须标注“结果未通过校验”，而不是静默保留为确定答案。

客户端按任务和字段累积；重连以**真实 Redis 事件 ID**恢复，去重、补发和完成态转换保持幂等。若字段无法可靠解析，则显示“正在整理结果”，直到完成解析或失败；不退化成原始 JSON 流。最终保存标准化结构、解析状态、原始输出以及提示词/模型/语言版本。旧任务保持兼容读取，不改写历史答案。

### 7.2 按题型显示

| 题型 | 生成中 | 完成后 |
| --- | --- | --- |
| 单选/多选 | 可稳定确认的答案出现即显示；解释文本持续追加。未确认时只显示状态，不猜选项 | 大号答案、分段原因及不确定性提示；无无关字段，无折叠、复制或点击要求 |
| 编程 | 进入 `code` 字段即增量渲染代码；短暂等待期显示准确阶段；绝不先渲染整段 JSON 再切换 | 完整代码及必要的算法要点/复杂度；语言与复制在 Web 提供，悬浮窗保持免点击 |
| 通用/调试 | 依据结构化 `answer`、`explanation`、`code` 等字段选择恰当布局 | 展示有用内容，不把未知字段伪装成代码 |

解释/分析字段可以包含 Markdown：在 Web 使用受限的 Markdown 渲染（段落、列表、行内代码、代码块）；桌面端可采用相同的只读渲染。禁止原始 HTML 与不受信任的外部资源自动加载。`code` 字段是代码文本，使用语法高亮，**不交给 Markdown 渲染器**。原始输出仅在 Web 详情的排查区可见；桌面悬浮窗不出现折叠控件。

## 8. 桌面端重设计

先输出独立的设计稿，覆盖 macOS/Windows 的实际浮窗尺寸、深浅主题和最窄窗口；设计评审通过后才开发。保持截图、局部截图、快捷键、窗口控制、透明度、远程控制和登录等既有能力。

1. **采集态：** 以截图缩略图与数量为中心，可明确识别“同题追加”和“新题重置”。快捷键动作成功/失败有轻量反馈，避免无响应；多张图片顺序可见。
2. **处理态：** 一行清楚的阶段状态和必要错误；提交后立即有反馈，重连与排队不显示假性 0% 卡住。
3. **结果态：** 选择题答案与原因优先，编程题代码优先。内容随字段流稳定增长，不闪烁、不跳回顶部、不横向溢出。悬浮窗内无必须点击的控件，不以大块快捷键说明占用视觉空间。
4. **设置态：** 账号、连接状态、快捷键、语言与窗口偏好分区；模型密钥和提示词主要在 Web 配置，桌面端只显示是否就绪和进入配置入口。

设计交付物：信息架构、四态线框图、桌面宽度/高度适配稿、字体/颜色/间距令牌、错误与空状态、键盘流程与可用性验收。先进行实际窗口的截图走查，再逐页替换旧 UI。**不能通过移除已有功能获得简洁感。**

## 9. Web 用户端重设计

目标是密度高、信息有用、操作路径短的工作台，不是营销落地页。桌面与移动端都要可用；内容区域按表格、分栏和详情组织，不用大面积空卡片和泛泛的功能说明。

- **全局框架：** 明确当前位置；账号菜单中有“退出登录”，退出时调用服务端注销并清理本地状态，返回登录页；管理员与普通用户导航不同。
- **工作台：** 最近任务、运行/排队/失败状态、连接可用性、需要处理的错误以及当前题型配置。删除无行动价值的指标和夸大尺寸的装饰块。
- **任务列表：** 题型、提交时间、运行耗时、状态、所用模型、语言与可用操作；支持服务器端分页、搜索、状态/题型/时间/用户（仅管理端）筛选；能打开详情、取消未完成任务、按权限删除历史。
- **任务详情/复习：** 截图按顺序显示；单选/多选以答案和理由为首，编程题以代码、算法与复杂度为首。显示警告、语言、模型和配置版本。原始 JSON 仅放开发/排查区域，默认不作为结果正文；复制复制的是实际答案或代码。
- **连接与模型：** 自有连接的增删改、掩码密钥、连接测试、模型能力和题型映射。每个操作有加载、成功、失败与回退状态，不提交无效配置。
- **提示词与语言：** 按题型编辑、预览、版本历史和恢复默认；编程语言默认值及逐任务覆盖。
- **设备与远程：** 连接状态、配对、断开及操作反馈，与任务历史中的设备来源相互关联。

页面设计先提交工作台、任务列表/详情、模型连接、提示词编辑、账号菜单、管理页的高保真稿及移动端关键状态；经视觉与交互评审，再实现组件与页面。使用统一的表格、表单、图标、状态标签、反馈组件和可访问的键盘焦点，不写无意义的说明文字。

## 10. Web 管理端

- **概览：** 活跃用户、排队/运行任务、失败率、各阶段延迟、Worker 和存储状态；指标可按时间范围筛选，异常有入口。
- **用户：** 搜索、分页、账户状态、注册与最近活动、任务量；启停和撤销会话需二次确认及审计；不可误操作自身唯一管理员账号。
- **任务与答案：** 按用户、题型、状态筛选；查看阶段事件、错误、配置版本、截图和按字段排版的答案。截图不可公开暴露，访问需记录。
- **审计：** 管理员对用户、任务、截图、提示词的访问和修改可检索，含时间、操作者、目标及结果。
- **模型运维：** 只管理系统支持的连接协议与运行状况，不拥有用户密钥，也不提供共享模型。

## 11. 数据、迁移与保留

沿用现有 `users`、`ai_tasks`、`answers`、`stored_files`、`user_configs` 与设备表，增量迁移：

1. 用户归属的 `provider_connections`（密文密钥、状态、版本）与 `user_models`（连接、模型 ID、能力）。
2. `question_model_defaults`：每用户每题型唯一，包含默认模型及语言策略。
3. `user_prompt_versions`：用户、题型、版本、模板、创建时间、启用版本；产品默认模板单独维护。
4. 任务配置快照或受控引用：连接/模型 ID、提示词版本、目标语言、流协议版本、解析版本；不含密钥。
5. 答案标准化字段与原文沿用现有表；需要时新增兼容字段，不破坏已有历史。
6. 管理审计与任务执行指标。

数据库修改仅通过版本化迁移；旧全局模型设置仅作一次性提示，不迁移成任何用户的密钥。**没有个人密钥的旧用户应进入“需要配置”的明确状态**。已保存答案保留，旧任务只读可复习。截图默认保留 30 天，可由用户提前删除；旧截图沿用其已有过期时间，不追溯延长。管理员设置保留策略前需提供部署级上限。答案默认保存到用户删除或账户删除。账户删除时清理密钥、截图与相关记录，并提供清理结果；审计记录按合规策略脱敏保留。默认保留期作为首版产品决策，评审时可调整。

## 12. 安全、测试与验收

### 12.1 安全边界

会话令牌不写入 URL 或日志。SSE 的任务令牌应具备短效、任务绑定、泄漏撤销和重连更新机制；不要在错误监控中记录查询参数。浏览器会话采用安全 Cookie、CSRF 防护和明确的跨站策略；桌面端凭据保存在系统安全存储而非渲染进程可读配置。对任意用户 URL、模型响应和 Markdown 均按不可信输入处理。管理员读取用户内容需最小权限和审计。

### 12.2 自动化

- 隔离：两个普通用户加一个管理员，覆盖任务列表/详情、SSE、截图链接、模型与提示词、设备、删除/取消和管理员边界；每个接口包含横向越权测试。
- 并发：多用户同时提交、单用户超额排队、一个用户模型超时、另一个用户成功、Worker 重启、重试、取消与迟到结果。
- 流协议：跨 chunk 的引号、转义、Unicode、数组、代码中的特殊字符、断流、重连、重复/乱序事件、最终 JSON 无效与旧答案回放。
- UI：桌面宽窄窗口的单/多选、编程、失败、重连、无配置状态；Web 登录/退出、筛选、详情、截图查看、BYOK、提示词编辑和管理员审计。
- 安全：密钥不出现在 API 响应、日志、错误、导出及截图；私网地址拒绝；Cookie、CSRF 和对象存储授权检查。

### 12.3 发布门槛

1. 10 名不同用户并发创建任务，至少 4 名用户同时进入推理，其他任务可见排队；没有跨用户串数据或无界阻塞。
2. 单选、多选和编程题在字段可确认后持续增量显示；没有“生成中原始 JSON -> 最终答案/代码”的整屏跳变。
3. 用户 A 通过任何普通 API、SSE、截图 URL 或设备接口都不能访问 B 的数据；管理员访问留审计；无用户密钥绝不调用共享密钥。
4. 编程语言从界面选择，经请求和任务快照到模型提示词，最终答案代码与目标语言相符。
5. Web 用户能从任务列表进入历史复习、按字段阅读答案、看自己的截图、退出登录；管理员能按权限查看用户任务与截图。
6. 所有新页面的设计稿先通过评审，再通过自动化与人工走查；失败、超时、空数据和窄窗口均无死路。

## 13. 实施顺序与拆分

这是一个**产品项目群**，不应作为单次巨型改动交付。每期有独立规格/计划、迁移与回滚路径：

| 阶段 | 交付边界 | 完成标志 |
| --- | --- | --- |
| A. 隔离与并发 | 用户归属审计、任务状态/取消、Worker 执行槽、公平调度、日志指标 | 双用户隔离测试和 10 用户并发压测通过 |
| B. 用户配置 | BYOK 连接/模型、题型映射、提示词版本、语言、任务快照 | 无个人密钥不能提交；每用户所选配置真实生效 |
| C. 流式契约 | 增量字段解析、可恢复 SSE、最终结果兼容、桌面即时展示 | 单选/多选/编程字段流和重连测试通过 |
| D. 设计与桌面重构 | 先评审设计稿，再替换采集/处理/结果/设置布局 | 功能不退化，窄窗口和免点击体验验收 |
| E. 设计与 Web 重构 | 先评审设计稿，再开发用户端与管理员端 | 任务复习、设置、退出、管理员截图和审计闭环 |
| F. 发布治理 | 压测、安全评审、迁移、回滚、监控和试用反馈 | 发布门槛逐项有证据，不凭页面演示判定完成 |

A、B、C 存在数据契约依赖，不能并行修改同一个任务协议；桌面/Web 的视觉设计可以在 A、B 开发期间并行，但页面实现必须基于已定协议。每阶段保持旧客户端可用或通过明确的版本兼容与发布窗口切换；不得直接在生产数据上运行未经验证的破坏性迁移。
