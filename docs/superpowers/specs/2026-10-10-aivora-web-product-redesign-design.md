# Aivora Web 产品化重构设计

**日期：** 2026-10-10
**状态：** 第一阶段设计
**范围：** 用户工作台、个人中心、管理员概览、用户与权益管理

## 1. 目标

将现有 Web 端从功能入口集合升级为可以长期使用的 SaaS 工作台。用户需要在进入页面后立即知道账号是否可用、剩余体验次数、授权有效期、模型是否配置完成以及下一步应该做什么；管理员需要能快速掌握系统运营状态并处理用户、授权和任务问题。

本阶段不改变现有注册、邮箱验证、授权码激活和任务计费规则，只重组页面信息架构、补齐用户端账户中心和管理员运营视图，并为后续扩展保留明确的数据边界。

## 2. 设计方向

- 产品定位：面向 AI 题目处理工具的工作型 SaaS，不做营销型落地页。
- 视觉方向：可信、克制、密度适中的运营工作台。
- 设计来源：`design-system/aivora/MASTER.md`，页面实现使用 `frontend-design-skill`，交互和可访问性使用 `ui-ux-pro-max` 校验。
- 技术栈：Next.js App Router、React、TypeScript、现有 CSS token、Lucide 图标。
- 视觉约束：不使用 emoji 作为图标；所有图标按钮有可访问名称；状态颜色不能作为唯一信息；桌面端和 375px 手机宽度都可用。

## 4. 用户端页面设计

### 4.1 AppShell

- 侧边栏保留桌面端固定导航，移动端改为顶部菜单或底部导航。
- 顶部栏显示当前页面上下文、账号头像、账号状态和退出操作。
- 个人中心通过顶部账号菜单和侧边栏均可进入。
- 导航项根据当前路径高亮，并保持浏览器前进后退可用。

### 4.2 工作台

第一屏按以下顺序排列：

1. 页面标题、问候和主要动作“打开桌面端”。
2. 权益状态横幅。
3. 任务、模型、桌面端连接等关键指标。
4. 最近任务。
5. 配置引导和帮助入口。

权益状态必须覆盖：

- 有效授权：显示到期日期和剩余天数。
- 有免费次数：显示剩余次数和“开始使用”入口。
- 次数耗尽：显示“激活授权码”入口。
- 授权过期：显示“激活新的授权码”入口。
- 邮箱未验证：显示重新发送验证邮件入口。

模型状态必须覆盖：

- 已配置可用模型。
- 未配置模型。
- 连接存在但模型不可用。
- 没有支持视觉识别的模型。

### 4.3 个人中心

个人中心采用“摘要 + 分区面板”布局：

- 账号信息：邮箱、验证状态、账号创建时间、最近登录。
- 我的权益：免费次数、当前授权、开始时间、到期时间、剩余天数。
- 激活授权码：输入、粘贴、提交、成功和失败反馈。
- 授权历史：授权码后缀、激活时间、有效期、状态。
- 使用记录：时间、题型、状态、消耗类型。
- 安全设置：修改密码、退出其他设备、注销账号。

授权码明文不在前端保存；提交后只根据服务端响应刷新账户快照。

### 4.4 任务中心和模型配置

本阶段只做结构统一和状态补齐：

- 任务页增加筛选栏、状态说明、错误原因和下一步操作。
- 任务详情保留截图、结果、原始输出和实时进度。
- 模型配置页面明确连接、模型、题型分配和提示词四个层级。
- 未完成配置时显示可执行的引导，而不是只显示空列表。

## 5. 管理端页面设计

### 5.1 管理概览

首屏展示：

- 用户总数、今日新增、活跃用户。
- 有效授权、即将过期授权、免费体验剩余总量。
- 今日任务、失败任务、服务健康状态。
- 待处理事项列表。
- 用户、授权、任务、模型的快捷入口。

待处理事项需要带可操作链接，例如“查看即将过期授权”，不能只显示静态数字。

### 5.2 用户与权益

用户列表字段：

```text
用户、邮箱验证、账号状态、角色、免费剩余次数、
授权状态、授权到期时间、最近登录、最近使用、操作
```

页面支持：

- 邮箱或用户名搜索。
- 账号状态、角色、授权状态、邮箱验证状态筛选。
- 免费次数耗尽和即将过期筛选。
- 分页。
- 用户详情抽屉。

用户详情抽屉分为：

- 基本资料。
- 使用概览。
- 当前权益。
- 授权历史。
- 最近任务。
- 模型配置状态。
- 管理操作。

危险操作必须二次确认，调整额度和授权操作必须显示操作结果并刷新详情。

## 6. 数据边界和接口

优先复用现有接口：

```text
GET  /api/account/usage
GET  /api/auth/me 或现有认证状态接口
GET  /api/ai/tasks
GET  /api/ai/models
GET  /api/admin/overview
GET  /api/admin/users
PATCH /api/admin/users/:id/status
GET  /api/admin/license-codes
GET  /api/admin/license-settings
POST /api/admin/license-batches
```

第一阶段需要补齐或统一：

```text
GET /api/account/me
GET /api/account/entitlements
GET /api/account/usage-history
GET /api/account/license-history
GET /api/admin/users/:id
PATCH /api/admin/users/:id/trial
GET /api/admin/users/:id/tasks
GET /api/admin/users/:id/entitlements
```

前端页面使用统一的 `AccountSnapshot`：

```ts
type AccountSnapshot = {
  user: UserProfile;
  usage: UsageSummary;
  entitlement: Entitlement | null;
  modelStatus: ModelStatus;
  desktopStatus: DesktopStatus;
};
```

若后端接口暂时不能一次性提供完整快照，前端通过独立服务层组合请求，不在页面组件中直接散落接口拼接。

## 7. 交互状态和错误处理

所有页面必须具备：

- 首次加载状态。
- 空数据状态。
- 请求失败状态。
- 操作进行中状态。
- 操作成功反馈。
- 操作失败反馈。

权益错误统一映射：

```text
EMAIL_NOT_VERIFIED   请先完成邮箱验证
TRIAL_EXHAUSTED      免费体验次数已用完，请激活授权码
ENTITLEMENT_EXPIRED  授权已过期，请激活新的授权码
ACCOUNT_NOT_ELIGIBLE 当前账号暂不可使用
```

## 8. 验收标准

- 用户打开工作台后 3 秒内能确认自己的使用资格和下一步操作。
- 个人中心可以完成授权激活并看到刷新后的有效期。
- 管理员可以从概览进入用户详情，并完成停用、恢复和额度调整。
- 页面不依赖 hover 才能发现核心操作。
- 375px、768px、1024px、1440px 宽度下无横向溢出。
- 键盘可以完成导航、筛选、打开详情和关闭抽屉。
- 所有图标按钮有 `aria-label` 或可见文本。
- 现有注册、授权、额度和任务测试继续通过。
