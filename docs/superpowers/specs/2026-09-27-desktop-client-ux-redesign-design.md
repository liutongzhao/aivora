# Aivora Desktop Client UX Redesign

## Goal

将 Aivora 客户端从“功能堆叠的 Demo 页面”重构为面向高频桌面使用的简洁工具：用户登录后能快速开始截图搜题，答案窗口优先呈现答案，设置和高级能力保持可发现但不打扰主流程。

## Product Principles

1. **核心路径优先**：截图、搜题、查看答案、复制代码是第一优先级。
2. **渐进披露**：常用操作默认可见，高级窗口控制、备用快捷键和诊断能力默认收起。
3. **状态代替解释**：使用短状态、图标、控件反馈替代长段教程和重复提示。
4. **一个功能一个入口**：设置、快捷键、远程控制不在多个页面重复出现。
5. **桌面工具感**：稳定尺寸、紧凑间距、低装饰、统一控件和键盘友好交互。

## Information Architecture

### Settings Window

使用固定标题栏和左右布局。左侧只保留用户能直接理解的产品功能分组：

- 工作台
- 快捷键
- 模型与提示词
- 窗口
- 连接
- 账户

工作台只展示登录状态、客户端服务状态、开始使用、最近一次任务和少量常用快捷键。远程控制、兼容性检测和更新状态归入“连接”，不再占据工作台的大块区域。“外观与系统”不再作为模糊分类，透明度、缩放、窗口尺寸和窗口位置统一归入“窗口”。

### Model and Prompt Center

“模型与提示词”是独立页面，内部使用顶部标签切换，避免将模型、题型分配和提示词堆成一个长页面：

- **模型**：管理用户模型、连接归属、图片能力、启用状态、同步、手动添加、编辑和调用测试。
- **题型分配**：为编程题、单选题、多选题、通用题和调试题选择默认模型；编程题和调试题额外配置输出语言。
- **提示词**：按题型切换并编辑提示词，显示保存状态和最近版本，支持保存、恢复上一版本和未保存修改提示。
- **连接选择**：模型页只选择已启用连接；连接的创建、编辑、测试和启停放在“连接”页面，避免重复表单。

模型页采用“列表 + 详情”的桌面布局。常用操作显示在当前模型行或详情区，新增和编辑使用侧边详情区或紧凑弹窗，不展开成占满页面的大表单。

客户端和外部端共享服务端用户配置。连接、模型、题型默认模型和提示词均以服务端数据为准，桌面端不维护另一套独立配置。页面进入、手动刷新或保存后重新读取服务端状态，发现配置在其他端发生变化时提示重新加载，避免静默覆盖。

### Exam Overlay

保留两个主视图：

- 队列：查看、删除和整理截图
- 答案：查看结构化答案、代码和复制操作

悬浮窗只展示队列、答案和处理状态，不承载设置中心功能。截图、局部截图、搜题、重置、窗口移动、透明度、缩放和其他高级动作均通过快捷键完成，不增加依赖鼠标点击的常驻操作按钮。

### Shortcut Management

默认展示：

- 截图
- 局部截图
- 搜编程题
- 搜单选题
- 搜多选题
- 通用搜题
- 显示/隐藏窗口
- 一键重置

高级窗口控制、滚动、备用快捷键默认折叠。修改快捷键采用行内录入，冲突在当前行反馈，并提供恢复默认操作。

## Visual System

- 设置窗口使用浅色中性背景，考试窗口保留深色高对比主题。
- 以蓝色作为主操作色，错误使用红色，成功使用绿色，避免多套强调色竞争。
- 统一按钮高度为 `32px` 或 `36px`，卡片和控件圆角控制在 `6px` 到 `8px`。
- 减少大面积阴影、渐变和装饰性圆角容器。
- 采用明确的标题、辅助文字、状态文字三级层级。
- 图标按钮使用 Lucide，并为非显而易见的图标提供 tooltip。
- 长说明只在首次引导、帮助弹窗或错误处理时出现，常态页面不保留。

## Interaction Rules

- 首次使用可以展示一次简短引导，之后不重复显示。
- 普通成功操作使用短暂 toast，不使用常驻说明卡。
- 只有需要用户处理的错误才显示持久提示。
- 快捷键录入时直接捕获组合键，保存后立即显示结果。
- 快捷键冲突必须阻止保存，并在对应行显示冲突对象。
- 开始使用按钮进入考试窗口后，设置窗口不再承担考试操作。
- 主题、窗口尺寸和透明度调整不改变主要任务路径。
- 模型、题型分配和提示词保存成功后使用短暂 toast 或行内状态反馈，不展示常驻说明卡。
- 模型同步只将外部连接发现的模型作为待添加项，用户明确添加后才进入自己的模型列表。
- 已停用连接下的模型不可被新的题型分配选择；当前配置失效时显示可处理的错误状态和替代操作。
- 提示词切换题型时保护未保存内容，离开编辑状态前提示保存或放弃。
- 服务端是模型和提示词配置的唯一来源，客户端刷新时以服务端结果覆盖临时展示状态。

## Implementation Scope

第一阶段：

- 建立客户端视觉 token 和基础控件样式。
- 重构 `ConfigPage` 为设置中心布局。
- 合并或收敛 `SettingsDialog` 的重复功能。
- 重构快捷键展示和录入交互。
- 增加“模型与提示词”页面及其四个内部标签。
- 将客户端模型、题型分配、提示词和连接请求统一封装为类型安全的 API 服务。

第二阶段：

- 重构 `SubscribedApp`、`Queue` 和 `Solutions` 的考试窗口布局。
- 减少流式处理和队列页面中的提示文案。
- 统一答案、代码、复制和重置操作。

第三阶段：

- 清理遗留说明、重复入口和不必要的用户提示。
- 补充页面级和快捷键交互测试。
- 使用桌面窗口尺寸验证设置页、队列页和答案页的溢出与布局稳定性。

## Non-Goals

- 不改变后端接口和 AI 任务协议。
- 不改变快捷键底层注册机制。
- 不删除远程控制、兼容性检测、自动更新等功能。
- 不在本阶段引入新的 UI 框架或大规模依赖。
- 不在客户端复制一套独立的模型或提示词存储。
- 不将管理员模型目录管理混入普通用户的桌面端配置；桌面端只管理当前用户可用的连接、模型和提示词。

## Acceptance Criteria

- 登录后用户能在一个首屏内找到并执行“开始使用”。
- 设置中心不再需要通过长页面滚动寻找主要设置。
- 常用快捷键和高级快捷键有明确层级。
- 修改快捷键、冲突提示、测试快捷键的流程清晰可完成。
- 用户能在客户端完成连接、模型同步、模型启停、题型分配和模型测试。
- 用户能按题型查看、修改、保存和恢复提示词，并能看到保存状态。
- 客户端和外部端打开同一账号时使用同一份模型与提示词配置，不产生静默分叉。
- 队列页和答案页的主要操作不依赖长段说明文字。
- 设置页、队列页、答案页在当前桌面窗口尺寸下没有明显溢出、重叠或跳动。
