# Aivora 多用户产品化交付路线图

**依据：** `docs/superpowers/specs/2026-09-25-aivora-multiuser-product-design.md`
**状态：** 待评审；本文件确定阶段边界，不代替各阶段的可执行计划。

## 交付原则

- BYOK-only；不存在共享密钥、管理员代调用或无密钥回退。
- 普通用户的资源归属由服务端会话确定；管理员通过独立、审计的接口访问。
- 旧任务与答案可读；版本化迁移、灰度切换、可回滚；不延长旧截图过期时间。
- 桌面与 Web 先交付实际尺寸的设计稿及交互状态，评审通过后才开发页面。
- 每阶段有自己的测试、回滚方式和验收证据，不以演示截图代替验证。

## 分阶段设计与验收关口

1. **A：** 压测至少 10 个不同用户近同时提交，其中至少 4 个不同用户同时推理；单用户超额排队，慢用户不阻塞快用户。模拟派发中断、Worker 进程退出、重试与取消；核对无重复模型调用、无串流或越权。数据库迁移只新增表/字段，旧客户端仍能创建与读取任务。
2. **B：** 先评审密钥加密/轮换与 HTTPS URL 校验策略，再测跨用户访问、密钥泄漏和禁用后的待执行任务。题型映射、版本化提示词和语言贯穿提交、快照、Worker、历史；老用户无密钥显示“需要配置”，不挪用环境密钥。
3. **C：** 先确定字段事件 schema 版本及客户端累积规则；用跨 chunk 转义、Unicode、数组、截断、无效 JSON、重复/乱序/重连与旧任务回放验证；结果页绝不先展示原始 JSON。
4. **D：** 设计交付信息架构、四态与错误空态、实际浮窗适配和设计令牌；人工窗口截图走查后才能替换旧 UI。截图追加/重置、局部截图、透明度、快捷键、登录和远程控制逐项回归。
5. **E：** 设计交付工作台、列表/详情、连接/提示词、账号菜单及管理员视图；再实现分页筛选、截图、结构化答案、退出、管理员审批和审计。用不同身份及移动端 E2E 核验。
6. **F：** 用可复现命令、指标看板和迁移演练逐项核对规范第 12.3 节。截图新记录默认 30 天，旧记录保持原过期时间；上线前演练清理、备份和回滚。

## 发布与回滚

- 每阶段先在测试环境执行 Flyway 增量迁移及旧数据回归，再灰度 API/Worker，最后切换客户端。涉及新协议时保持旧响应读取，客户端版本不满足时给出明确升级提示。
- A 的回滚为停止新调度器、等待/取消在途租约并恢复旧 Worker/派发路径；只有租约与状态对账后才允许回退，不能直接切换造成双重调用。新增表暂时保留供重试与审计。
- B/C 的回滚不得回退已加密密钥或删除旧答案；D/E 的回滚为 UI 版本切换，服务端保持兼容。F 需记录负责人、窗口、指标阈值和实际结果。

## 暂不在本轮详细计划中的决策

B 的密钥加密主密钥管理、轮换与测试部署策略，C 的事件字段/版本合同，D/E 的设计稿及交互评审，F 的正式发布基础设施尚需在各阶段计划编写前确认。它们是明确的设计门槛，不是允许实现时临时猜测的空白。
