# Aivora 本地开发与验收

## 服务拓扑

| 服务 | 地址 | screen | 启动方式 |
| --- | --- | --- | --- |
| Electron/Vite | `http://127.0.0.1:54321` | `aivora-dev` | `npm run dev` |
| Web 管理端 | `http://127.0.0.1:3000` | `aivora-web` | `npm run dev --prefix web -- --hostname 127.0.0.1 --port 3000` |
| FastAPI API | `http://127.0.0.1:18000` | `aivora-backend` | Conda 环境 `aivora-backend` + Uvicorn |
| Celery Worker | Redis 队列 | `aivora-worker` | Conda 环境 `aivora-backend` + `--pool=prefork --concurrency=4` |
| PostgreSQL | `127.0.0.1:15439` | Docker | `aivora-postgres` |
| Redis | `127.0.0.1:16379` | Docker | `aivora-redis` |
| MinIO | `127.0.0.1:19000` | Docker | `aivora-minio` |

## 启停命令

```bash
./scripts/start-aivora.sh
./scripts/check-aivora.sh
./scripts/stop-aivora.sh
```

脚本只会操作以上四个 Aivora screen，不会停止电脑上的其他项目服务。启动脚本发现同名 screen 已存在时会按当前代码重启。

## 从旧调度模式切换

首次应用 V016 迁移前，先停止旧 API 接收新任务，让旧 Beat 和 Worker 完成所有在途任务。确认 PostgreSQL 中没有 `created`、`queued`、`processing`、`streaming` 任务，且 Redis 的 `aivora` 队列为空后，再停止旧 Worker/Beat 并执行迁移。V016 遇到在途任务会拒绝执行，不会直接丢弃任务。

本地核查：

```bash
docker exec aivora-postgres psql -U aivora -d aivora -c \
  "SELECT status, count(*) FROM ai_tasks WHERE status IN ('created','queued','processing','streaming') GROUP BY status"
docker exec aivora-redis redis-cli LLEN aivora
```

这两处都清空后，部署新 API/Worker。旧消息若仍滞留在 Broker 中，可能携带旧的两个参数，不能交给新 Worker 执行。

## 代码验证

```bash
conda run -n aivora-backend pytest -q
conda run -n aivora-backend python -m compileall -q backend/app
npm test
npm run typecheck
npm run build
npm run e2e --prefix web
```

Web 开发服务运行时不要执行 `npm run build --prefix web`。如果需要构建，先执行 `screen -S aivora-web -X quit`，构建完成后再运行启动脚本。

## 截图到答案验收路径

1. 用户在 Electron 或 Web 创建会话并登录。
2. 客户端向 `POST /api/ai/process-screenshot` 提交 Base64 截图、题型和语言。
3. API 将图片写入 MinIO，原子提交任务和图片记录，然后立即投递 Celery；Redis 作为消息队列，不保存任务图片输入。
4. Worker 原子抢占 `queued` 任务，从 MinIO 读取图片并调用用户配置的 OpenAI 兼容接口。
5. Worker 通过 Redis Stream 发布 `progress`、`content`、`completed` 或 `error` 事件。
6. 客户端使用短期 SSE Token 连接 `GET /api/ai/stream/{task_id}`，按事件增量显示答案。
7. 完成后答案写入 `answers`，同时保存结构化 JSON、原文、解析状态和 warning。

Celery 重投递遇到已处于处理中的任务时，只标记 `WORKER_LOST_UNCERTAIN`，不会再次调用可能已计费的模型。上传过程中若进程突然退出，未提交的 MinIO 对象需要通过对象存储生命周期规则或人工清理；没有常驻清理服务。

## 本地模拟 Provider

`tests/e2e/mock_openai_server.py` 提供确定性的 OpenAI 兼容 SSE 服务。桌面端闭环测试需要显式设置 `AIVORA_DESKTOP_E2E=1`，避免普通 Web 测试机误启动 Electron。
